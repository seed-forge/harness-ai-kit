# Reference: NL2SQL / Text2SQL 领域落地范例

> 本文是 `devlab-ai-agent-engineering` 的领域 reference。只沉淀**可迁移的方法论原则与典型坑规避**，不绑死具体库/版本/字段名。

## 分层管道落地（NL2DSL2SQL 两阶段）

```
自然语言 → [NL2DSL] → DSL(中间表示) → [DSL2SQL] → SQL
             │                          │
   理解: 意图识别/查询类型分类       编译: 方言适配/JOIN 生成
   抽取: 条件/metric/时间/实体        校验: 语法+语义校验
   检索: 知识增强(字段/术语映射)
```

- **DSL 中间表示解耦**：让 NLP 层与工程实现层解耦，一份 DSL 可编译到多种 SQL 方言；决策可追溯（审计/合规友好）。
- **查询类型先分类再分策略**：明细 / 指标(metric) / 排名(ranking) / 对比 等，路由到各自 strategy，避免巨型分支。

## 核心决策：规则优先 + LLM 兜底

- 字段/术语映射、条件抽取优先走规则 + 检索；不足时触发 LLM 兜底。
- 触点分模型：普通归一化用便宜模型，复杂条件抽取用强模型。

## 典型坑（方法论化）

| 坑 | 方法论原则 |
|----|-----------|
| RAG 直接按字段匹配识别主表 → 主表识别错、召回不精准（检索 N 张表实需 2-3 张） | 表识别要**语义分析 + 条件驱动反向查表**，不能只靠向量检索 topN；召回后需按"条件字段归属"二次筛表 |
| LLM 兜底永不触发（"最小条件数=0"使 0 条件也算充足） | 兜底触发阈值要表达"规则不足"的**真实语义**，避免形式化默认值让兜底形同虚设 |
| ranking 与 metric 策略职责混淆，衍生指标缺失 | 策略职责边界要清晰；"多指标/衍生指标"类查询稳定归类到具备该能力的策略（metric 链路） |
| LLM 5s 超时：返回 200 但未完成 | 超时值匹配真实耗时分布；区分"连接成功"与"生成完成" |
| 前后端契约：groupBy 对象数组 vs 字符串数组；datasource_id str vs int | 跨服务字段类型/结构要有契约校验（见 devlab-contract-web-server），不靠约定俗成 |

## 配置工程

- 配置分层：LLM 相关配置在 `llm_fallback.touchpoints.*`，非 LLM（排序/裁剪）在 `ranking.*`。
- 提供强制 override（如 `force_query_type`）用于调试与灰度。
- "配置既不过度也不缺失"：每个可变项可配，但不为不存在的需求预留开关。
