# Reference: 语音数字人前端领域落地范例

> 本文是 `devlab-ai-agent-engineering` 的领域 reference。只沉淀**可迁移的方法论原则与典型坑规避**，不绑死具体厂商 SDK/组件名。

## 分层管道落地（语音对话闭环）

```
拾音(ASR) → 理解(LLM/Dify) → 生成回复 → 播报(TTS+数字人渲染) → 状态机
   │VAD          │                │流式chunk      │onPlayBegin/End
```

- 语音交互是**强时序 + 多异步事件**系统，核心难点在"事件时序对齐"与"状态机一致性"。
- 用**适配器**隔离不同数字人/ASR/TTS 厂商 SDK："新增一个 tech 模式"= 新增 adapter，不改上层。

## 典型坑（方法论化）

| 坑 | 方法论原则 |
|----|-----------|
| 文字立刻回显但 TTS 延迟数秒 → 文字/声音不同步 | 文字显示要**由播报事件驱动**（等 onAvatarPlayBegin 再显示），而非收到文本即显示 |
| 多段 TTS 串音（上一段未完下一段就播） | 分段播报由 **onAvatarPlayEnd 精准串接**，维护播报队列，禁止并发触发 |
| 打断后残留片段继续播 | 打断需**清空整个 TTS 队列 + 调用 SDK interrupt**，而非只停当前片段 |
| ASR 停不下来，持续识别噪声 → 无限对话循环 | 明确 ASR 生命周期与静音/超时停止条件；噪声帧需过滤 |
| VAD 时序：Begin 只准备不激活、激活异步、End 前音频丢失 | 会话激活要在 Begin 即完成或**用音频队列缓冲**跨越异步激活窗口 |
| 麦克风启动首段漏收音 | 录音就绪前的音频要缓冲，避免"开口即丢" |
| 浏览器 `NotAllowedError`：未交互前 play() 失败 | 音频上下文必须**用户交互后解锁**；音频 MIME 类型显式修正(如 octet-stream→audio/wav) |
| 前端环境变量：敏感凭据暴露 / 前缀缺失取不到 | 敏感凭据(密钥)**绝不进前端**，token 刷新走 SDK/后端；仅按构建工具约定前缀暴露非敏感变量 |
| TTS 纯文本 vs 界面 Markdown 渲染混淆 | 播报用纯文本、渲染用富文本，**两条内容通道分离** |
| 改到了 deprecated 组件而非现役组件 | 改动前先确认现役入口，废弃组件要清晰标注/隔离 |

## 规则/LLM 分工

- 本地 QA/固定话术走本地规则库(localQA)，命中则不触发 LLM；未命中再走 LLM 服务。
- 业务分流（是否需鉴权/转人工）由规则判定，前端只调接口不做业务决策。
