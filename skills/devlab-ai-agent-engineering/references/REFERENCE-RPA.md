# Reference: 桌面 RPA / GUI 自动化领域落地范例

> 本文是 `devlab-ai-agent-engineering` 的领域 reference。只沉淀**可迁移的方法论原则与典型坑规避**，不绑死具体库/分辨率/坐标。

## 分层管道落地（感知-决策-执行环）

```
感知 → 决策 → 执行 → 校验 → (循环)
 │       │      │       │
定位窗口  路由动作 点击/复制 剪贴板/OCR
读取消息  分类     滚动/发送 结果校验
OCR识别   去重
```

- GUI 自动化本质是"**有噪声的感知 + 不可靠的执行**"，每步执行后都要**回读校验**，不能假设动作必然成功。

## 典型坑（方法论化）

| 坑 | 方法论原则 |
|----|-----------|
| 固定像素坐标在高分屏(DPI 缩放)失效；窗口 API 返回逻辑像素非物理像素 | 用**相对百分比布局**而非绝对像素；显式处理 DPI 缩放；坐标随窗口尺寸自适应 |
| 滚动/复制前窗口未聚焦 → 操作静默失效 | 任何键鼠操作前**先确保目标区域聚焦/激活**；读取前先激活窗口并打开目标会话 |
| 复制后剪贴板为空被当成"无内容" | 剪贴板为空往往是**点到空白/误操作**，需重试/微调定位；发送前校验剪贴板防误覆盖 |
| 仅用内容 MD5 去重 → 同内容不同时间被误判重复 | 去重键要含**业务时间戳**（内容+业务时间复合去重）；业务时间取自消息头而非抓取时刻 |
| 批量读取停不下来 / 提前停止 | 明确**停止条件**：最大历史数、到顶检测、连续旧消息阈值；`max_scroll` 类配置要真实生效 |
| 从底部向上读取导致倒序发送 | 读取顺序与业务顺序解耦；发送前按业务时间**正序重排** |
| OCR 多区域轮询慢、易错 | 配**优先识别区域**减少轮询；常见混淆字符纠错(O→0/l→1)；必要时预处理(放大/加粗)提准 |

## 规则/LLM 与适配

- 规则优先：定位、去重、分类等确定性逻辑走规则；仅在语义判断（如消息类型模糊）时才引入模型。
- 用适配层隔离不同目标应用/OCR 引擎，换目标=换 adapter。

## 评测

- 用真实样例目录（如 `docs/evaluate/{text,image}`）做回归；支持**单文件测试**避免全量耗时。
