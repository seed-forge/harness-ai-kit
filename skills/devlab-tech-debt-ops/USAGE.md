# devlab-tech-debt-refactor — Usage

## Overview
技术债清理/重构编排方法论（非业务债）：现状梳理固化 → 建安全网 → 拆分设计 → 引用清零安全移除 → 回归验证，全程小步可回退、行为不变。

## When to use
- god-class/引擎腐化，改动风险高。
- 需在不改行为前提下拆分解耦。
- 大范围搬迁/删除旧实现。

## References
- `references/REFERENCE-DESIGN-PATTERNS.md` — 设计模式清单 + 示意性伪代码（点到即止）。

## 可直接复制的中文 Prompt

```text
用 devlab-tech-debt-refactor 处理这个技术债：
1) 先梳理 <目标类/模块> 现状并固化成 md（架构/流程/职责/问题分层 P0-P3），不改代码；
2) 确认将改动行为的测试安全网是否够；
3) 给拆分设计（模块划分+职责边界+迁移映射），按需选设计模式但不过度；
4) 出小步可回退的重构任务清单，删旧代码前先"引用清零"再删再测。
目标：行为不变、结构变好。业务语义若要变请提醒我改走 spec 驱动。
```
