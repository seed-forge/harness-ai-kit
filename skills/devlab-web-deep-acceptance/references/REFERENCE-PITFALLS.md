# REFERENCE-PITFALLS — 深度验收实战陷阱库（72 条五段式）

> 来源：大型存量 Web 系统（Vue2 微前端 + Element 二开组件库 + Oracle 代理层）全量深度验收实战，
> 72 条全部有实锤出处，已通用化为与具体项目无关的模式；实证字段保留原始场景日期备查。
> 每条五段式：**症状 / 根因 / 错误尝试 / 正确解法 / 经验总结**。
> 标注【已框架化】的条目表示机制已固化进 `scripts/`（执行器/precheck/审计），新落地项目开箱即有。
>
> **追加规则**（多会话防撞号）：①追加前重新 grep 本文件取当前最大号（别用会话早期旧快照）；

## 一、选择器与组件库适配（1-9）

### 1. 二开组件库 DOM 前缀与文档不符
- **症状**：按 Element/AntD 官方文档写的 `.el-*/.ant-*` 选择器在业务页基本点不中。
- **根因**：前端用了组件库二开换肤版，DOM 类名整体换前缀（实证：`.es-tree-node/.es-table/.es-message-box`）。
- **错误尝试**：盲目调 nth/模糊文本匹配，用例脆弱且误伤同名元素。
- **正确解法**：盘点期先读组件库源码（`ui-components/src/components/`）确认真实类名，选择器统一用真实前缀；疑难交互（自定义双击、私有关闭钮）直接读组件实现。
- **经验总结**：存量系统第一件事是确认组件库真实 DOM 契约，文档不可信，源码是事实源。
- **实证**：Element 二开库全模块，2026-07。

### 2. 组件自实现"双击"（点击计数器）使合成 dblclick 无效
- **症状**：树/列表"双击展开"用 Playwright `dblclick()` 永不触发。
- **根因**：组件双击不是原生 dblclick 事件，而是 300ms 窗口内自实现点击计数器。
- **错误尝试**：加大 delay 重试 dblclick、改用 dispatchEvent(new MouseEvent('dblclick'))——均无效。
- **正确解法**：同一 tick 内连发两次 `node.click(); node.click()`；非法节点弹 alert 时关掉换下一个节点重试。
- **经验总结**：遇到"双击"交互先读组件源码确认是原生事件还是计数器模拟，再选触发方式。
- **实证**：全局左树组件，2026-07。

### 3. 同名按钮/label 全局撞车
- **症状**：点"查询"却命中顶部全局栏的查询；"同步"误配"单位同步"。
- **根因**：门户框架顶栏/左右栏与业务区存在大量同名文本元素。
- **错误尝试**：`page.click('text=查询')` 靠 Playwright 严格模式报错才发现撞车。
- **正确解法**：定位一律限定业务容器（左栏/右栏/主容器），按钮用精确文本正则 `/^\s*查询\s*$/`；撞名严重页用容器作用域 + waitFor visible + DOM 兜底点击。
- **经验总结**：存量门户系统"文本即定位"必须带作用域，精确正则优先于模糊匹配。
- **实证**：control-manage 等模块，2026-07-28。

### 4. 表格行数统计被 fixed 列重复行污染
- **症状**：断言表格行数总是实际行数的 2 倍。
- **根因**：带 fixed 列的表格组件会在 fixed 区渲染一套重复行 DOM。
- **错误尝试**：数 `tr` 总数后除 2——列配置变化即崩。
- **正确解法**：只数主体区 `.table-body-wrapper .table-row`（按实际组件类名适配）。
- **经验总结**：表格类断言先搞清组件的 DOM 分区（主体/fixed 头/fixed 列），只观测主体区。
- **实证**：control-manage `_helpers.tableStats`，2026-07。

### 5. 复合输入控件内含隐藏 input，取值撞车
- **症状**：日期范围控件取 form-item 内第一个 input 的值得空串。
- **根因**：复合控件 form-item 内混有 checkbox 等隐藏空值 input，按位置取第一个必撞。
- **错误尝试**：`.first()` / `nth(0)` 碰运气。
- **正确解法**：直接取控件专属 class 的 input（如 `input.range-input`）的 value。
- **经验总结**：复合控件取值定位到控件自身标识，不按 form-item 内 DOM 顺序猜。
- **实证**：control-manage stku-l1-load，2026-07。

### 6. 下拉同值重选不触发 change，waitForResponse 必超时
- **症状**：select 选型操作后等响应，间歇性 30s 超时。
- **根因**：页面 mounted 已自动选中同值并发过请求，再选同值组件不发 change、不发请求。
- **错误尝试**：延长超时、加重试——治标且拖慢全量。
- **正确解法**：选前读当前值，同值则跳过等响应；需验证切换链路的用例先切另一值再切回。
- **经验总结**："操作后必有请求"是脆弱预设，先确认操作是否真的产生了状态变化。
- **实证**：role-manage `selectRoleLv`，2026-07。

### 7. 通用栅格类名不能定位业务栏；纯图标按钮无文本
- **症状**：(a) 按 `.col-12` 类定位业务容器，命中的是顶部导航；(b) 导出按钮按文本"导出"找不到。
- **根因**：(a) 门户栅格类名全页复用（实证单页 18 个）；(b) 图标按钮渲染为 `svg use #icon-xxx` 无文本节点。
- **错误尝试**：`nth(0/1)` 碰运气、靠 title 属性猜。
- **正确解法**：(a) 业务容器按可见标题 filter hasText 定位；(b) 图标按钮定位 `svg:has(use[*|href="#icon-xxx"])`，断言用 `waitForEvent('download')`+文件名。
- **经验总结**：布局类名≠语义；图标按钮的语义在 svg symbol id 里。
- **实证**：role-manage 探针，2026-07。

### 8. 异步字典/远程下拉 emit undefined 致渲染崩溃白屏
- **症状**：页面加载即 Vue TypeError（`.length` of undefined）白屏。
- **根因**：checkbox/radio 型异步字典加载瞬间把 v-model emit 成 undefined，页面未加空守卫。
- **错误尝试**：误判为"数据缺失"去造数——方向全错。
- **正确解法**：识别"加载即 TypeError"模式多为异步组件 emit 时序问题；测试侧 `(x||[]).length` 判空；产品侧属真缺陷（缺空守卫）。
- **经验总结**：白屏先分诊是数据问题还是前端空守卫缺陷，二者处置路径完全不同。
- **实证**：acquisition-quality 白屏根因，2026-07。

### 9. 树 DOM 文档顺序 ≠ 树深度
- **症状**：按"最后几个节点"选叶子，命中的是浅层非法节点。
- **根因**：懒加载树的 DOM 顺序是展开顺序而非层级顺序。
- **错误尝试**：nth 倒序选节点。
- **正确解法**：按组件的叶子标识 class（如 `.is-leaf`）筛选；深层目标节点用逐层展开的专用选择原语。
- **经验总结**：树操作三问：叶子标识是什么？是否懒加载？目标在第几层？然后写专用选择器，不复用通用 nth。
- **实证**：data-collect，2026-07。

## 二、导航、时序与环境（10-18）

### 10. SPA hash 导航遗留脏状态
- **症状**：跨用例 DOM 残留、mounted 不触发、同 URL hash 不重载。
- **根因**：keep-alive 页签不随路由变、组件复用、hash 变化不触发整页重载。
- **错误尝试**：goto(hash) 后等 networkidle——等到的还是旧页面状态。
- **正确解法**：跨用例统一 `page.reload()` 全新挂载；导航封装在一个 gotoPage 原语里全项目复用。
- **经验总结**：SPA 测试的页面隔离只能靠真 reload，hash 跳转不是导航。
- **实证**：微前端全模块，2026-07。

### 11. 等待就绪用业务组件轮询而非固定 sleep
- **症状**：sleep(3000) 在慢机器上不够、快机器上浪费，全量时间被拖垮。
- **根因**：固定时长与真实渲染进度无关。
- **错误尝试**：不断加长 sleep。
- **正确解法**：`waitForFunction` 轮询业务组件出现（表格/表单项/树/canvas）或主容器文本量阈值，再留短固定窗口给 mounted 回填。
- **经验总结**：等待条件必须锚定业务就绪信号，sleep 只作兜底补充。
- **实证**：全模块，2026-07。

### 12. 微前端整页白屏间歇 FAIL
- **症状**：同一用例单跑时好时坏，白屏无任何报错。
- **根因**：微前端子应用加载竞态，偶发主内容区为空。
- **错误尝试**：判 FAIL 改用例——越改越乱。
- **正确解法**：导航后验主内容区非空，空则再 reload 一次（弹性导航原语 gotoPageResilient）；新模块直接复用不重写。
- **经验总结**："导航成功"不等于"页面挂载成功"，导航原语必须内含挂载验证。
- **实证**：data-collect，2026-07。【已框架化：`lib/api-common.js gotoPageResilient`】

### 13. 输入不触发框架响应式等于没输
- **症状**：脚本设值后点登录/查询，系统提示"请输入"。
- **根因**：直接设 `input.value` 绕过 Vue 响应式，v-model 未更新。
- **错误尝试**：keyboard.type 逐字敲（慢且对已有值处理麻烦）。
- **正确解法**：设值后 `dispatchEvent(new Event('input',{bubbles:true}))`。
- **经验总结**：Vue/React 项目脚本设值必须补框架事件，这是登录/session 原语的标配。
- **实证**：lib/session.js，2026-07。

### 14. 间歇 5xx/404 只有"重试成功"才豁免
- **症状**：同一接口这次 500 下次 200，用例结果飘忽。
- **根因**：共享环境后端抖动客观存在，但"间歇"也可是真缺陷前兆。
- **错误尝试**：见 500 就豁免（掩盖真缺陷）或见 500 就 FAIL（误报淹没真缺陷）。
- **正确解法**：豁免白名单机制——URL 命中豁免模式**且同路径稍后 2xx** 才记 exempted（每条豁免模式必须附证据注释"为什么不是本页缺陷"）；持续失败照常 FAIL。
- **经验总结**：豁免是带证据的核销，不是过滤；豁免表每一条都要能回答"凭什么"。
- **实证**：lib/browser.js EXEMPT_RETRY_PATTERNS，2026-07。【已框架化：config.exemptRetryPatterns】

### 15. 全量连跑的 FAIL 先单跑复验再定性
- **症状**：--all 连跑报 7 个 FAIL，单跑复验 6 个 PASS。
- **根因**：连跑资源竞争/状态污染/共享环境抖动放大。
- **错误尝试**：按连跑结果直接登记缺陷——6 个假缺陷。
- **正确解法**：终态以单跑/分批稳定态为准；后端问题用 curl 空参直调 3 次稳定复现才定性（区分 token 失效与业务 500）；框架级用 `--retry N` 案例级重试，重试成功判 pass 并注记。
- **经验总结**：全量结果只作筛查，单跑稳定态才是终态事实。
- **实证**：control-manage，2026-07-28。【已框架化：run.js `--retry`】

### 16. 共享环境故障禁止会话自行重启
- **症状**：dev server OOM 崩溃/后端 down，会话想"帮忙"拉起。
- **根因**：多会话竞相重启共享服务会互相冲突（端口占用、状态不一致），已有实锤。
- **错误尝试**：nohup 拉起继续跑——与其他会话重启打架。
- **正确解法**：探活确认不可达 → 停下当前批次上报用户等恢复 → 期间做不依赖环境的工作（写用例/盘点/报告）；恢复后从中断功能点继续。
- **经验总结**：环境问题是人的决策域（HD-2），会话只处理"代码修复后的流水线部署"。
- **实证**：用户确立规则，2026-07-29。

### 17. 执行器内置前端 preflight 探活 fail-fast
- **症状**：dev server 中途崩，后续 15 个用例各 30s 超时全被误判用例缺陷。
- **根因**：环境死了但执行器不知道，每个用例白等超时。
- **错误尝试**：逐个分析超时用例——方向全错。
- **正确解法**：login 前探活，不通直接 `Fatal: 前端未就绪` 退出码 2；看到 Fatal 按陷阱 16 处置，不要改用例。
- **经验总结**：fail-fast 探活把"环境死"与"用例坏"在源头分开，省的是整批误判的时间。
- **实证**：role-manage，2026-07-29。【已框架化：run.js preflight + 退出码 2】

### 18. 工具链多版本并存时先确认运行时版本
- **症状**：脚本语法/依赖在"自己机器"正常，CI/共享环境报错。
- **根因**：不同用途进程要求不同 runtime 版本（实证：dev server 要 node v12、e2e 脚本要 v20，PATH 分别注入）。
- **错误尝试**：统一升级到最新——dev server 直接起不来。
- **正确解法**：环境台账登记每类进程的 runtime 版本与 PATH 注入方式；多会话并行时登录间歇超时先探活再重试，不直接判用例缺陷。
- **经验总结**：runtime 版本是环境事实，写进台账（.devlab），不要写进用例假设。
- **实证**：2026-07。

## 三、断言与数据甄别（19-25）

### 19. 假删除：断言状态变化而非行消失
- **症状**："删除"用例断言行消失，永远 FAIL。
- **根因**：后端是逻辑删除（update 状态列），列表 SQL 不过滤已删行。
- **错误尝试**：怀疑删除没生效，反复重试。
- **正确解法**：断言"接口 200+提示+重查状态回显"；其他模块删除用例前先查后端确认真删/假删。
- **经验总结**：删除语义先读 mapper，逻辑删除是存量系统常态。
- **实证**：账号管理，2026-07。

### 20. 非 200 业务码先判真假失败
- **症状**：写操作返 90001（业务失败码），但数据实际已落库（或反之返 200 但没落库）。
- **根因**：两种真坑——(a) 假失败：主操作生效但日志/回滚逻辑有缺陷报错码；(b) 假成功：insert SQL 残缺/类型解析恒 false/NOT NULL 未传，服务日志零痕迹。
- **错误尝试**：只看接口返回码下结论。
- **正确解法**：写操作断言一律以 list 复查/DB 直查为准；探针直调+复查区分真假；UI 行文本有渲染时序误判，以响应体字段为准。
- **经验总结**：写链路的事实源只有一个——落库结果。接口码、UI 回显都是线索。
- **实证**：role-manage save-role，2026-07。

### 21. 日志/记录类页面 200+空数组 ≠ pass-empty
- **症状**：操作日志页永远空，接口 200。
- **根因**：高概率是埋点/入库链路断了（入库断链），而非"没人操作过"。
- **错误尝试**：标 pass-empty 收工。
- **正确解法**：一律标"疑似入库断链"登记 pending-issues，按断链判定规则（操作必达+表存在+仍空）实证后定性。
- **经验总结**："记录类页面为空"在存量系统是缺陷信号，不是数据信号。
- **实证**：2026-07。

### 22. pass-empty 判定前先验表存在性（铁律）
- **症状**：页面 200+空，判"无数据"去造数，造完还空。
- **根因**：表根本不存在——DB 代理层吞 ORA-00942 表不存在错误返空，接口层无法区分"空表"与"无表"。
- **错误尝试**：直接造数（白跑）、判后端缺陷（误判）。
- **正确解法**：开测前一条 SQL 批扫模块主表存在性（`all_tables`，主表清单从 mapper FROM 抽取）；缺表→预标"接口层假成功"，有数据分支直接 blocked；建表 DDL 超会话授权登记 pending；INSERT 返 200+"0 行"同理以 DB 直查复核。
- **经验总结**：空结果三问：表在吗？查询条件对吗？真的没数据吗？顺序不能反。
- **实证**：data-collect 实锤，2026-07。【已框架化：precheck 表级预检】

### 23. 统计页 200+空的三分法（必走 DB 探针实证）
- **症状**：统计/报表页永远空，但源表明明有数据。
- **根因**：三种可能——(a) 默认日期范围过窄（数据在别的日期）；(b) 组织域不匹配（账号不在数据归属组织）；(c) 源表真空。
- **错误尝试**：不区分直接造数，造完日期/组织依然不匹配。
- **正确解法**：DB 直查源表：`group by trunc(stat_date)` 看日期分布、`group by org_code` 看组织归属、`count(*)` 看总量；按分诊结果分别驱动（改查询日期/换组织域数据/造数）；registry 执行注写明表名+实证。
- **经验总结**：统计页空结果是一个分诊问题，三分法每种都有可执行的下一步。
- **实证**：acquisition-quality，2026-07。

### 24. 树懒加载空子级是合法的
- **症状**："展开后节点数必增"断言间歇 FAIL。
- **根因**：部分节点本来就没有子级（`result:[]` 是合法响应）。
- **错误尝试**：判接口缺陷。
- **正确解法**：以响应体 result 长度为准逐节点尝试，不预设每个节点都可展开。
- **经验总结**：树的断言锚定响应体事实，不锚定结构预设。
- **实证**：2026-07。

### 25. 无数据时 L4 跳转用路由注册等价验证
- **症状**：L4（跳转/链接有效性）用例因列表空无法点行内入口。
- **根因**：表空无行可点，但路由注册与否是可独立验证的事实。
- **错误尝试**：为了点入口强行造数（成本高）或标 blocked 放弃（覆盖率损失）。
- **正确解法**：等价替换——`$router.resolve({name}).matched.length>0` 验路由注册（捕获坏链），再 routerPush 实测挂载无 JS 错，报告注明等价替换。
- **经验总结**：L4 的本质是"链路有效"，行内点击只是其中一种触发方式。
- **实证**：acquisition-quality `_l4.js`，2026-07。

## 四、高危操作与权限（26-28）

### 26. 弹窗"取消"按钮可能是真实提交
- **症状**：以为点"不通过/取消"是安全退出，实际触发了不可逆状态流转。
- **根因**：审批弹窗的每个按钮都绑定真实业务动作（实证："通过"=状态 03、"不通过"=状态 04，两个都不可逆）。
- **错误尝试**：测试时随手点"取消"退出弹窗。
- **正确解法**：盘点时读源码确认每个弹窗按钮的真实行为登记 registry；不可逆流转只对 AUTOTEST_ 前缀记录执行且选影响最小分支；触达真实设备的下发类一律降级到弹窗/表单层不真实提交（HD-1）。
- **经验总结**：弹窗没有"安全按钮"，每个按钮的行为以源码为准。
- **实证**：EquipVersionApprove，2026-07。

### 27. 高危下发页用硬闸双保险 + 探针防污染
- **症状**：需要验证"下发"按钮存在且可点，但绝不能真发。
- **根因**：无确认弹窗的直发按钮，一旦点击即真实下发。
- **错误尝试**：人工小心点击——共享环境迟早出事。
- **正确解法**：硬闸（page.route 拦截下发 URL）+ 自检探针双保险；探针请求必须带专用标记只 abort 不记录，否则污染拦截命中计数误报"拦截失效"；拦截不生效即自我中止。
- **经验总结**：高危操作的测试护栏本身也要被测试（探针），且探针不能污染护栏的观测数据。
- **实证**：control-manage，2026-07。

### 28. 权限守卫可能已过时
- **症状**：页面/按钮不显示，疑似"账号权限不足"。
- **根因**：权限模型演进后旧守卫代码没删（实证：省级管理员角色判断已迁移，旧 v-if 还在）。
- **错误尝试**：按权限不足标 blocked，或去 DB 乱加权限。
- **正确解法**：对照权限迁移记录确认现行守卫逻辑，按新模型修正认知；不把过时守卫误判成权限问题。
- **经验总结**：权限类 blocked 前先问"这个守卫代码是现行的吗"——历史守卫是存量系统的常见化石。
- **实证**：2026-07-27 权限模型变更。

## 五、用例工程与多会话协作（29-72）

### 29. Sub-Agent 并行写用例：给足模板，禁止其跑执行器
- **症状**：Sub-Agent 产出的用例风格不一、缺硬约束、或与主会话浏览器冲突。
- **根因**：agent 缺少 helpers API 清单/参考用例/硬约束上下文；多个浏览器实例抢环境。
- **错误尝试**：让 agent 自由发挥 + 自己跑 run.js 验证。
- **正确解法**：prompt 含 helpers API 清单、参考用例路径、硬约束（硬闸/降级/BLOCKED 协议）、语法自检命令；执行由主会话统一串行跑；大盘点交 GeneralPurpose 写文件只回摘要（长报告会被截断）。
- **经验总结**：并行产出的质量上限=模板与约束的完备度；执行权必须收归主会话。
- **实证**：control-manage 37 用例 3 agent 并行，2026-07。

### 30. 新建脚本可能延迟落盘；批量改 YAML 必须回验
- **症状**：Write 报成功但 node 找不到文件；批量回写后 YAML 解析炸。
- **根因**：IDE/文件系统同步延迟；reason 含冒号未加引号、CRLF/LF 混行。
- **错误尝试**：立即执行新脚本失败后反复重写。
- **正确解法**：先 sleep 3-5s 重试，仍不行写到相邻目录执行后清理；批量改 registry 的脚本写完必须 js-yaml 回验。
- **经验总结**：文件写操作不可信即时性，YAML 写操作不可信格式——两者都要回验。
- **实证**：2026-07。

### 31. 别按表格思维预设功能点
- **症状**：预设"翻页"功能点，最终 blocked=页面无分页组件。
- **根因**：盘点时按"列表页=表格+分页"的惯性思维建模，没看真实页面结构（实证：账号管理页是左查询表单+组织树、右详情面板，无表格）。
- **错误尝试**：按预设功能点写用例再逐个 blocked。
- **正确解法**：先看源码结构再定功能点；L1 硬条件按页面真实形态等价替换。
- **经验总结**：功能点从页面真实结构生长出来，不是从测试模板套出来。
- **实证**：2026-07。

### 32. 模块级全页 503 先查部署，再判环境抖动
- **症状**：同一模块所有接口持续 503。
- **根因**：服务从未部署（无进程/无 jar/无日志目录）≠ 间歇抖动；另有新拉服务预热期（~1 分钟）首批请求间歇 500。
- **错误尝试**：按抖动豁免，或误判前端缺陷。
- **正确解法**：查部署侧"三无"判定从未部署；自行构建部署（注意构建脚本白名单登记要求）；预热期首轮 FAIL 先重跑再定性；本地拉起的服务重启环境失效，registry 注明。
- **经验总结**：503 的第一分诊维度是"部署了吗"，其次才是"稳吗"。
- **实证**：smart-distribution-station，2026-07-27。

### 33. HTTP 200 ≠ 业务成功：响应体分诊
- **症状**：接口全 200 但页面数据不对/为空。
- **根因**：DB 代理层吞错家族三形态——(a) 200+body `code:500`；(b) 200+`result:null`；(c) 200+空响应体（空体=报错、`[]`=合法零行）。
- **错误尝试**：只断言 HTTP 状态码。
- **正确解法**：用例断言和探针一律解析 body（bodyVerdict 六态：no-hit/http:N/code:500/result:null/empty/data）；"数据空需造数"结论必须先过陷阱 22 表存在性校验。
- **经验总结**：在代理层存在的架构里，HTTP 层与业务层是两套事实，断言必须穿透到业务层。
- **实证**：smart-distribution-station，2026-07-27。【已框架化：`lib/api-common.js bodyVerdict`】

### 34. fixed 定位弹窗用 offsetParent 判可见必误判
- **症状**：弹窗已打开但断言"未打开"（测试侧假失败）。
- **根因**：fixed 定位元素 `offsetParent` 恒为 null。
- **错误尝试**：用 offsetParent 过滤可见弹窗。
- **正确解法**：`getComputedStyle().display !== 'none'` + `getBoundingClientRect().width > 0` 判可见。
- **经验总结**：可见性判定要考虑定位方式，fixed/absolute 元素需用 computed style 路径。
- **实证**：smart-distribution-station，2026-07-27。

### 35. canvas 图表交互两级兜底
- **症状**：echarts/地图点击命中率极低（数据点位置不可预测）。
- **根因**：canvas 无 DOM 语义，坐标即运气；另有事件绑在 title/icon 子元素、权限静默拦截等变体。
- **错误尝试**：硬算坐标死磕像素级命中。
- **正确解法**：先网格坐标扫描几个点；不中则 page.evaluate 取组件根 `__vue__` 直调事件方法，报告注明"等价替换：验证跳转/联动逻辑而非像素级命中"；点击无响应还要想到权限静默拦截分支，不只怀疑选择器。
- **经验总结**：canvas 测试的断言目标是行为结果，不是像素事件；等价替换要如实注记。
- **实证**：smart-distribution-station 4 用例兜底成功，2026-07-27。

### 36. 页面专属树 ≠ 全局树，结论不可跨页传导
- **症状**：全局树探测"无台区叶子"，但某页专属树明明有。
- **根因**：页面内嵌树与全局树数据源/meta 配置不同。
- **错误尝试**：用全局树结论给页面树判死刑；Sub-Agent 中断即重派（产物其实已落盘）。
- **正确解法**：每页树单独探测；可用"目标页 mounted 读 $route.query 则 URL 带参直航"绕行左树；Sub-Agent 中断先查工作区落盘产物再决定重派；脚本改文件用 `\r?$` 容忍 CRLF。
- **经验总结**：同类组件不同实例=不同数据契约，探测结论的作用域仅限被测实例。
- **实证**：smart-distribution-station，2026-07-27。

### 37. 树节点类型不同需不同选择策略，成功检测用多候选 label
- **症状**：用叶子筛选器选中间节点永远选不到；用浅层策略选深层节点够不到。
- **根因**：树的不同层级节点类型（单位/台区/终端）结构特征与交互路径完全不同（实证：台区是非叶中间节点，埋在线路懒加载子节点里）。
- **错误尝试**：一个通用 selectNode 打天下；单 label 判定选中成功（各页字段名不统一致假失败）。
- **正确解法**：按节点类型写专用选择原语（渐进展开+懒加载分页处理）；成功检测内置多候选 label 列表命中任一即返回；限全局树，页面内嵌树另探。
- **经验总结**：树选择策略的维度=节点类型×深度×加载方式；选中判定要对页面字段命名差异免疫。
- **实证**：line-loss 探针实锤，2026-07-29。

### 38. 造数前必做"三查"：对象类型、列型、列宽
- **症状**：造数接口返 200 但 0 行落库，或值被截断/吞掉。
- **根因**：(a) 目标是 VIEW 不是表（插视图 0 行）；(b) 列是 NUMBER 插了字符串被吞；(c) 列宽 VARCHAR2(20) 中文超宽。
- **错误尝试**：信 insert/update 返回值判断造数成功。
- **正确解法**：三查 SQL——`user_objects` 查对象类型（视图要查 `user_dependencies` 找底表插底表再回验推导列）、`user_tab_columns` 一把拿列型+列宽+可空；造数后必须 DB 直查计数回验（factory 自带 verify 清单）。
- **经验总结**：DB 代理层吞异常的环境下，造数的事实源只有落库计数；三查是造数的前置门禁。
- **实证**：charging-pie-monitor 三连实锤，2026-07-27。

### 39. 造数值的"后端硬解析格式"先读 service 代码
- **症状**：造数后接口 500（数组越界）或 update 被吞假成功。
- **根因**：后端对列值有硬编码解析格式（实证：`前缀#v1;...;v96` 按 split 硬取 96 段）；拼出的值超列宽被吞；SQL 执行器按 `;` 切语句，字符串字面量内分号把语句切碎（静默少插行）。
- **错误尝试**：按业务语义造"合理"值。
- **正确解法**：盘点阶段 grep service 里目标列的 split/parse 调用，格式约束写进 seed SQL 注释；分号字符用 `chr(59)` 拼接规避。
- **经验总结**：造数格式的事实源是消费端代码，不是业务直觉；seed 执行器的语句切分规则也是契约。
- **实证**：charging-pie-monitor，2026-07-27。

### 40. 方言缺陷会被空表掩盖，造数后必须全量重探
- **症状**：接口长期 200+空"伪健康"，造数后突然 500。
- **根因**：PG/Oracle 方言错误（如 interval 比较）在全表无行时 join 短路不求值不报错，有数据才真正求值引爆。
- **错误尝试**：造数后只验造数目标接口——其他接口的雷还在。
- **正确解法**：造数落库后重跑模块全接口探针；静态扫 mapper 时对方言形态（interval、`::`、`substring(` 等）一次性全文件标记，不等运行期逐个暴雷。
- **经验总结**：空表是方言缺陷的完美伪装；"造数后全量重探"应成为造数 SOP 的固定末步。
- **实证**：charging-pie-monitor tmnl-status，2026-07-27。

### 41. $route.params 驱动页必须链式导航进入
- **症状**：直接 gotoHash/刷新后页面空白不发请求，无报错。
- **根因**：页面 `mounted` 读 `$route.params` 才发请求，params 非 URL 可持久，刷新即空。
- **错误尝试**：误判"页面坏"；L1 用例单独 gotoHash 永远 FAIL。
- **正确解法**：盘点时标注此类页，用例写链式导航 helper（从入口页真实点击进入）；L1 归链式进入后断言；深链并发突发在共享网关下易丢包，持续 FAIL 先串行直调同批端点定性环境类。
- **经验总结**：盘点时必须识别页面的参数来源（query 可直航 / params 必须链式），这决定用例结构。
- **实证**：charging-pie-monitor，2026-07-27。

### 42. 多选下拉的 tags 容器拦截点击
- **症状**：对多选 select 的 input click 必 30s 超时（`intercepts pointer events`）。
- **根因**：多选模式渲染的 tags 容器覆盖在 input 上拦截指针事件；选项后下拉不自收起。
- **错误尝试**：单选的点 input 模式直接复用到多选。
- **正确解法**：多选必须点 select 容器 + `{force:true}`，选完按 Escape 收下拉；盘点时看源码是否带 `multiple` 属性预判。
- **经验总结**：单选/多选是两套交互契约，选择原语分开写。
- **实证**：power-off-analysis，2026-07-28。

### 43. 单发接口豁免链失效：工厂级定向重试兜底
- **症状**：页面只发一次的接口间歇 404/500，豁免机制永远兜不住。
- **根因**：豁免前提是"同路径稍后 2xx"，但 mounted 单发接口失败后无重试机会，进不了豁免。
- **错误尝试**：放宽豁免条件（把真缺陷也豁免掉）。
- **正确解法**：两层——①命中已知抖动服务前缀按证据入豁免表；②用例工厂 catch 后判定"失败全部为某服务 404/500/503 且无 JS 错"才定向重跑一次，通过在 detail 注记；判定条件收紧防止把真缺陷重试成 pass。
- **经验总结**：重试分两级——案例级黑盒重试（--retry）与根因判定后的定向重试，互补不替代。
- **实证**：power-off-analysis，2026-07-28。

### 44. 导出断言以 download/Blob 为准，拦截器误报是假失败
- **症状**：导出文件已正常下载，但 monitor 判 JS 错误 FAIL。
- **根因**：通用响应拦截器对 Blob 响应按 JSON 结构校验报 console.error；另有导出按钮文本以源码为准（实证是"生成报表"非"导出"）。
- **错误尝试**：把拦截器误报当真缺陷修，或按猜测文本点按钮超时。
- **正确解法**：导出用例以 `waitForEvent('download')` 或 Blob 响应为成功信号；该 console.error 模式附证据入模块噪声表；同时登记 pending 推动拦截器对 blob 豁免。
- **经验总结**：二进制响应是通用 JSON 拦截器的盲区，断言锚定浏览器 download 事件这一最终事实。
- **实证**：power-off-analysis dom-l2-export，2026-07-28。

### 45. 大模块同构用例用"规格表工厂 + 薄存根"组织
- **症状**：56 个功能点逐个手写 .case.js，维护爆炸、豁免/重试策略改一处漏十处。
- **根因**：L1 加载/L2 查询重置高度同构，差异只在参数（apis 捕获表/表清单/是否手动查询/左树/前置）。
- **错误尝试**：复制粘贴改参数。
- **正确解法**：`_specs.js` 规格表 + 工厂函数（makeLoadCase/makeQueryResetCase），`<id>.case.js` 只留两行存根，脚本批量生成；复杂用例（L3 写链路/探索型）仍单独写；工厂内判定分支必须有探针实证注释。
- **经验总结**：同构用例的资产形态是"规格表"不是"文件堆"；工厂化让策略调整一处生效。
- **实证**：power-off-analysis，2026-07-28。

### 46. feature id 模块内必须全局唯一（带页面前缀）
- **症状**：多页重复 `l1-load/l2-query` id 互相覆盖用例文件，`--case` 无法定位。
- **根因**：执行器按 `cases/<module>/<feature-id>.case.js` 映射文件。
- **错误尝试**：事后改名（用例/报告断链）。
- **正确解法**：盘点写 registry 时就用页面缩写前缀（`ov-l1-load/dp-l3-archive/md-l4-goto-detail`）；同构用例工厂模式压缩。
- **经验总结**：feature id 是文件系统主键，命名规范在盘点期一次定对。
- **实证**：collection-exception，2026-07-29。

### 47. 码表同一语义多套写法并存，只补插不改存量
- **症状**：某服务查字典返空致整模块自动首查断（树接口 200 空→初始化不触发）。
- **根因**：码表中同一组码值并存两套键约定（实证：`abnorType` 小写驼峰与 `ABNOR_TYPE` 大写下划线），各有服务依赖。
- **错误尝试**：把存量行改成统一写法——炸掉另一族服务。
- **正确解法**：grep 两种写法各自使用方，复制存量行改 type 补插新组，绝不改存量；SQL 归档带回滚语句；症状识别：同模块多页同时"首查不发+树空+prop 警告"先查共同依赖的字典/树接口。
- **经验总结**：存量系统的码表是多约定沉积层，加法永远安全，改法是连锁炸弹。
- **实证**：collection-exception 一修解 8 页，2026-07-27。

### 48. body-code:500 归因用"正负对照行"实验，数据假设最多证伪 3 轮
- **症状**：接口 200+code:500，分不清"造数不完整"与"后端行处理缺陷"。
- **根因**：500 可能在结果行处理路径——命中行即炸、不命中则 200/0。

### 56. 裸 partition by 缺 order by（Oracle ORA-30485）被吞成 200+空

- **经验总结**：方言缺陷形态要进静态扫描清单一次扫全模块；后端-SQL 类修复可移交 devlab-dao-sql-compat。

### 68. seed SQL 的静态基线日期会腐化，必须日期宏替换

- **错误尝试**：后续会话重跑全模块才发现，返工改 SQL。
- **正确解法**：归档 SQL 保留写入时日期作可读快照，factory 加载时运行时替换为动态日期（映射表：快照日→D-1/D-2、月首日→当月首日）；用例内设日期的操作同样运行时计算。
- **经验总结**：时序类造数从一开始就用日期宏模式，"可读快照+运行时替换"兼顾可读性与防腐。
- **实证**：voltage-quality-monitoring，2026-07-29。

### 69. 造数第四查：join 条件列必须填非 NULL 真实值
- **症状**：主查询有行但某聚合列恒空/恒 0，弹窗无入口。
- **根因**：seed 行按业务语义把"可空"列置 NULL，但聚合子查询的 join 条件含该列，NULL join 失配断链。
- **错误尝试**：误判后端缺陷。
- **正确解法**：造数前 grep mapper 抽目标表参与的全部 join/子查询条件列，这些列一律填真实档案值（哪怕业务上"可空"）；症状识别：主查询有行但聚合列恒空，先查该列来源子查询的 join 键是否被 NULL 断链。
- **经验总结**：造数三查（对象类型/列型/列宽）加第四查（join 列非 NULL），NULL 是聚合断链的头号元凶。
- **实证**：voltage-quality-monitoring，2026-07-29。

### 70. 路由名前缀包含关系使 hash 断言 includes() 恒真
- **症状**：跳转未发生但 `url.includes('xxx/xxx')` 仍为真，假 PASS 掩盖真失败。
- **根因**：路由族同词根（Overview/Detail/Stat 同前缀），前缀包含关系使子串匹配恒真。
- **错误尝试**：includes 断言图省事。
- **正确解法**：L4 hash 断言一律末尾精确匹配 `/\/target$/.test(hash)` 或全等；盘点时留意同词根路由族；长会话偶发不触发的动线项用例内 ≤3 次重试。
- **经验总结**：URL 断言的默认形态是精确匹配，includes 只在确认无前缀族时使用。
- **实证**：voltage-quality-monitoring，2026-07-29。

### 71. registry 与 SUMMARY 状态漂移：四对齐核数 + 以 SUMMARY 为事实源回填
- **症状**：总账 progress、registry、SUMMARY 三方数字失同步（实证：30 条 pass 被记 todo、13 条被重置 todo，覆盖率虚低 43 条）。
- **根因**：回写框架化之前终态只存在于 SUMMARY；registry 扩容/重建/单跑复验后未执行条目停留 todo。
- **错误尝试**：认领模块见大量 todo 就盲目重测（浪费轮次）。
- **正确解法**：①收尾把三对齐扩为四对齐——registry status × .case.js × 报告 × SUMMARY/总账 progress 数字一致；②修正回填以带日期的 SUMMARY 为事实源（先比对报告文件 mtime 判新旧），逐条带 `# 回填自 SUMMARY（日期 三对齐修正）`执行注，fail/blocked 连 reason 回填，回填后 yaml 回验；③认领时发现 registry 大量 todo 但总账 done → 先回填再决定测什么。
- **经验总结**：多份状态文件必漂移，核数要四方对齐，回填要带事实源注记。
- **实证**：synthesis-query/role-manage，2026-07-31。

### 72. registry 模块粒度=认领单元，产品语义对齐用锚点字段，禁止物理合并
- **症状**：为对齐前端一级 APP 想合并多个 registry 模块。
- **根因**：合并代价——feature id 跨页冲突互相串写（静默数据损坏）、巨模块不可并行认领且一轮跑数小时、cases/reports/factory 历史资产全部断链；且前端一级模块本身有漂移（空壳目录、生成产物错指），不是稳定锚点。
- **错误尝试**：物理合并 registry 文件。
- **正确解法**：①单模块 yaml 顶层 `app: <路由模块目录名>` 锚点字段挂接（子域模块另加 `app_path:`），总账同步；②新模块 id 命名 `<app-kebab>-<域>`，存量不改名（增量迁移）；③APP 维度覆盖聚合与盲区清单用工具从路由源码自动建映射；已实锤的模块名↔APP 语义漂移在锚点注记在案。
- **经验总结**：执行单元与产品语义是两层，用锚点字段关联而非物理合并；增量迁移优于存量改名。
- **实证**：用户批准的结构决策，2026-07-31。
