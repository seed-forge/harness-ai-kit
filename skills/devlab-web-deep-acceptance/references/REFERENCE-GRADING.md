# REFERENCE-GRADING — L1-L4 深度分级模型

> 深度验收的分级标准。每个功能点在 registry 中标注 level，执行按 L1→L4 推进。

## 分级定义与硬条件

| 级别 | 内容 | 硬条件 |
|------|------|--------|
| **L1** | 页面加载 | 无 JS 错误、无 API 失败；有数据（表格 ≥ min_rows）；无 null/undefined/NaN 字面量渲染 |
| **L2** | 只读交互 | 查询/筛选/翻页/排序/Tab 切换/详情弹窗/图表渲染，断言结果与操作匹配 |
| **L3** | 写交互 | 新增/编辑/删除/状态切换，**真实提交**，以接口响应体 + 复查（必要时 DB 直查）验证 |
| **L4** | 跨页联动 | 跳转带参、hash/路由变化 + 目标页正常加载 |

## 分级细则

### L1 页面加载

- 导航到目标路由 → 等待业务组件挂载（轮询等待，**不用固定 sleep**：轮询业务容器出现
  或主内容区文本量 ≥ 阈值，再留 2-3s 给 mounted 回填）；
- 断言三件套：① `monitor.collect().jsErrors` 为空；② `apiFailures` 为空；③ 数据形态
  （表格行数/树节点数/卡片数 ≥ data_requirement.min_rows）；
- 表格单元格脏值扫描：前 N 行无字面量 `null`/`undefined`/`NaN` 文本；
- **`monitor.reset()` 必须放导航之前**——放导航后会把 mounted 阶段错误清掉造成 L1 假 PASS。

### L2 只读交互

- 每个查询/筛选/翻页/排序/Tab/弹窗/图表各一个功能点；
- 断言"操作 → 请求 → 响应 → 渲染"全链：捕获目标 API 响应体（六态分诊，见
  REFERENCE-FALSE-SUCCESS），并验证 DOM 结果与操作语义一致；
- 自动查询页（mounted 即发查询）注意：gotoPage 可能在请求发出前返回，用
  `captureApis.waitForHit(key)` 轮询等目标请求到达再 collect（否则间歇误判"接口未发起"）。

### L3 写交互

- **真实提交**（含审批流转），但只动测试前缀数据（如 `AUTOTEST_`）；
- 不可逆操作选影响最小分支；触达真实设备的下发类**降级到弹窗/表单层验证**（不真实下发）；
- 断言三链：接口响应体成功 + 列表/详情复查回显 + 必要时 DB 直查复核（写入接口返回 200
  不代表落库——代理层可能吞 SQLException 返 null/0）；
- 假删除甄别：删除可能是状态翻转（列表 SQL 不过滤），断言"状态变化"而非"行消失"，
  动手前先查后端确认真删/假删；
- 依赖易耗数据的用例开头自愈补数，保证 `--all` 可重复。

### L4 跨页联动

- 断言目标页 hash/路由变化用**末尾精确匹配**（`/\/target$/.test(hash)` 或全等）——
  路由名前缀包含关系（Overview/Detail 同词根）会使 `includes()` 恒真造成假 PASS；
- 无数据时（表空无行内跳转入口）用等价验证：`$router.resolve({name}).matched.length>0`
  验路由注册（捕获坏链），主目标再 routerPush 实测挂载无 JS 错；
- 路由参数驱动页（`$route.params` 刷新即空）必须链式导航进入，L1 归链式进入后断言，
  不单独 gotoHash。

## 等价替换规则

硬条件不是教条，按页面真实形态等价替换：

- **无表格页**（左查询表单+右详情面板）：L1 的"表格 ≥ min_rows"替换为"详情面板渲染 +
  关键字段非空"；预设"翻页"功能点在无分页组件的页面是伪需求；
- **图表/canvas 页**：像素级点击命中率低，两级兜底——先坐标扫描几个点，不中则
  `page.evaluate` 取组件根 `.__vue__` 直调事件方法，报告注明"等价替换：验证跳转/联动逻辑
  而非像素级命中"；
- **导出类**：以 `page.waitForEvent('download')` 或 Blob 响应为成功信号，不看 console
  （响应拦截器对 Blob 的 JSON 结构校验报错是假失败）；
- 等价替换的判定分支必须有探针实证注释，不凭预设。

## 功能点优先级（与 level 正交）

registry feature 可同时标 priority（P0-P3）：

- **P0**：主链路必经（登录后首页、核心查询、核心写操作）；
- **P1**：高频业务功能；
- **P2**：低频/管理配置类；
- **P3**：边角/即将下线。

多会话认领模块按模块级 priority 排序；模块内执行按 L1→L4，同 level 内 P0 先行。
