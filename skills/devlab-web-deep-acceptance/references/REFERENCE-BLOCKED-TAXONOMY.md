# REFERENCE-BLOCKED-TAXONOMY — 失败分类、blocked 规范与问题闭环

> 深度验收不是"全 pass 才算完"，而是"每个功能点有可信终态"。blocked 是一等公民：
> 不可修问题正确登记比强行判 fail 更有价值。

## 一、失败五分类路由表

| 根因类 | 判定依据 | 处置 |
|--------|---------|------|
| **前端** | JS 报错/组件未挂载/请求体拼错 | 修视图/API 层 → 部署 → 重跑该功能点 |
| **后端-SQL** | API 500 + SQL 异常（ORA-\*/方言形态） | 修 mapper → 部署 → 重跑 |
| **后端-逻辑** | 500/400 非 SQL；NoSuchMethodError 等 | 修 controller/service 或登记 pending-issues 标 blocked |
| **数据** | 200 但空/脏/缺前置 | 先按三分法甄别（断链/缺表/日期组织域）→ 造数工厂补造 |
| **环境** | 服务 down/网关不通/间歇抖动 | **停下上报等恢复**；间歇重试成功入豁免表 |

### 分类细则与常见误判

- **模块级全页 503 先查服务是否部署**：同一模块所有接口持续 503 ≠ 间歇抖动——
  先查部署侧有无进程/jar/日志目录（三无=从未部署）。新拉服务预热期约 1 分钟内
  首批请求会间歇 500/不发起，首轮 FAIL 先重跑再定性。
- **权限守卫可能过时**：权限模型变更后旧守卫（如"省级管理员"）可能失效，
  按现行模型修正，别误判"账号权限不足"blocked。
- **前端"坏引用"缺陷模式**：页面调用的组件方法/事件全库 grep 0 匹配即实锤
  （页面照已被替换的旧版组件写的），运行时症状为 created/render TypeError 或交互静默
  无响应。修法：不臆测旧组件行为，对齐同模块其他正常页的现行模式。
- **历史"已修复"登记不可信**：认领模块后以当前源码复核历史报告提及的修复点
  （仓库重组期修复易回滚/丢失），复现时注明"历史修复丢失"而非新发缺陷。
- **数据行关联用例**：单跑 PASS、全量 BLOCKED 是合法的——用例内自检前置抛
  `BLOCKED:` 而非 FAIL，保证 --all 可重复且终态保守可信。

## 二、blocked reason 规范

`BLOCKED:` 协议：`Error('BLOCKED:<五分类>——<原因+解锁命令>')` 不计失败，回写 blocked。

格式：`BLOCKED:<分类>——<一句话根因>，解锁命令：<具体命令/操作>`。例：

```
BLOCKED:数据类——.run-state.json 无 frozenAccount，需先 node tools/freeze-account.js <账号> frozenAccount
BLOCKED:后端缺陷类——PageHelper count 包裹含 CLOB distinct 必炸（问题 AM-4），登记 pending-issues
BLOCKED:环境类——模块服务从未部署（207 无进程无 jar 无日志），已上报
BLOCKED:前端-框架级——功能完整但 es 组件库 render 告警被 app errorHandler 吞掉，超模块范围，登记 pending-issues 问题 PM-1
```

要点：
- **必须含解锁命令/解锁条件**——下一个会话（或用户）看到能直接行动；
- **疑似入库断链**（日志/流水类 200+空）标 blocked 并关联断链分析，不记 pass；
- **前端-框架级**（功能实测完整但被框架吞掉的 render 告警）：不 silent-filter 成 pass
  （会掩盖框架缺陷），也不判 FAIL（功能没坏），标 blocked 登记 pending；
- 同一功能点修复 **≤3 轮**，超过登记 pending-issues 标 blocked 继续下一个，不死磕。

## 三、pending-issues 闭环

`docs/pending-issues.md` 是跨功能点问题的闭环载体。条目格式：

```markdown
## 问题 <模块缩写>-<序号>: <一句话标题> (YYYY-MM-DD <批次> 新增)

**影响功能点**: <module> / <feature-id>（<名称>）
**症状**: <现象 + 接口/错误码 + 取证方式（探针脚本/直调 body）>
**根因分析/实证链**: <编号列出证据，标注源码位置/日志行号/DB 查询结果>
**待处理**: <谁来修、修什么>
**优先级**: P0 阻断 / P1 重要 / P2 非阻塞 / P3 优化
**状态**: <待修复/暂缓/跳过-用户单独处理/已解决✅>
```

- 编号规则：**模块前缀 + 模块内自增**（防撞，见 REFERENCE-REGISTRY-SCHEMA 第四节）；
- 已解决移入文末"已解决问题"节，写解决方式+验证结果，同步更新文头统计表；
- 环境类问题一句话上报，不深挖日志（专项排查除外）。

## 四、豁免表纪律（间歇抖动）

框架豁免机制（`e2e.config.js` 的 `exemptRetryPatterns`）：URL 命中且**同路径稍后 2xx**
（重试成功）才记 exempted 不记失败；持续失败照常 FAIL。

- 每条豁免**必须附证据注释**（哪轮实测、什么模式、为什么不是本页缺陷）；
- 页面只发一次的接口失败后无重试机会，豁免链失效——用例工厂级兜底：catch 后判定
  "失败全部为该服务 404/500/503 且无 JS 错"才整页重跑一次，通过在 detail 注记
  "首轮间歇失败重试通过"；判定条件收紧，防止把真缺陷重试成 pass；
- 豁免仍计数并写入报告"豁免统计"段。

## 五、高危操作处置

- **盘点时读源码确认每个弹窗按钮真实行为**——"取消"按钮可能是真实提交（两个按钮都不可逆）；
- 不可逆流转只对测试前缀记录执行，选影响最小分支；
- 触达真实设备的下发类一律**降级到弹窗/表单层验证**，不真实提交；
- 无确认弹窗的直发按钮：**硬闸双保险**——`page.route` 全局拦下发 URL（armHardGate）+
  自检探针带标记只 abort 不记录（防污染拦截统计误报"拦截失效"），拦截不生效即自我中止。

## 六、造数约定（数据类 blocked 的解锁侧）

- 只动测试前缀（`AUTOTEST_`）数据，SQL 必须归档 `sql-scripts/`（带日期与用途注释+回滚语句）；
- 造数前"三查"：①查对象类型（`user_objects`——视图要 `user_dependencies` 找底表插底表）；
  ②查列型（NUMBER 列插字符串被吞无报错）；③查列宽（中文超宽/拼接值超 VARCHAR2 上限被吞）。
  一条 SQL 全拿：`select column_name||':'||data_type||'('||data_length||')' from user_tab_columns
  where table_name='X'`；
- **造数后必须 DB 直查计数回验**，不信写接口返回值（代理可能返 200 但 0 行）；
- **造数前扫目标表在 mapper 里的全部 join/子查询条件列，join 列必须填非 NULL 真实值**
  （NULL join 失配→聚合列恒空，别误判后端缺陷）；
- 造数后**全量重探同模块接口**——方言缺陷会被空表掩盖，造数后才引爆；
- seed SQL 的静态基线日期会随时间腐化：归档保留快照日期，factory 执行时做日期宏替换
  （快照日→D-1/D-2、月首日→当月首日）；用例内日期同样运行时计算别硬编码；
- 字符串字面量内的分号会把按 `;` 切分的 SQL 执行器切碎（静默少插行）——分号用
  `chr(59)` 拼接规避（Oracle）或等价转义。
