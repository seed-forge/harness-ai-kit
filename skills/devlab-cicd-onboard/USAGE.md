# Usage

## 可直接复制的中文 Prompt

```text
分析当前仓库并为它设计最小可行的 CI/CD。先识别语言、构建工具、测试命令、构建产物、已有 CI 配置和部署边界；不要假设任何内部主机、凭据或平台。优先复用现有 CI 提供商；若没有，给出 GitHub Actions 方案。输出需要我确认的部署目标、Secret 名称和审批点，再生成可审查的文件改动和验证步骤。
```

```text
把当前 CI 流水线的部署环境从 development 调整为 staging。先读取现有工作流和项目配置，列出会影响的 Secret、环境变量、制品和回滚路径。不得在仓库中写入真实凭据或主机地址；缺失的运行环境信息请输出 escalation，而不是猜测。
```

```text
为这个项目增加一个不会默认阻断发布的质量门。说明门应该放在哪个阶段、使用什么可重复命令、阈值由谁维护，以及如何用一次失败和一次成功验证它。先给出 patch 和验证计划，等待确认后再启用阻断。
```
