# 专利审查维度详细说明

> 本文档是 `patent-review` 技能的专题引用文档，定义了7个审查维度的详细检查方法、反例和修复模板。

## D1：数据流闭合

### 检查方法

对每个步骤，从步骤间数据流汇总表出发，验证：
1. 该步骤的每个输入是否有明确的前序步骤输出作为来源
2. 该步骤的每个输出是否被后续步骤明确读取
3. 数据结构表（字段处理记录、会话状态等）中的每个字段是否有明确的写入时机和读取用途
4. 是否存在"表格列了但正文未说明如何生成/更新/传递"的孤儿子段

### 典型反例

| 反例类型 | 说明 |
|---------|------|
| 孤儿计数器 | 字段配置表定义了"连续冲突阈值"，但字段处理记录中无"连续冲突次数"字段，也没有递增规则 |
| 接口字段缺失 | 文档A要求前序导办传入"导办策略版本来源"，但文档B的导办结果对象中无此字段 |
| 步骤输出未在汇总表中体现 | S6回退分类后写入了5个子集合，但步骤间数据流汇总表的S6输出行未列出 |

### 修复模板

- 孤儿字段：在数据结构表中补充该字段的写入时机和读取用途；或从配置表中删除
- 接口缺失：在双方文档中各增加一行字段定义和传递说明

## D2：术语一致性

### 检查方法

1. 抽取所有枚举值（状态名、错误代码、动作编号、用户类型、材料项状态等）
2. 全文搜索每个枚举值的每次出现，验证是否与定义表一致
3. 重点检查实施例段落中的术语是否与正文定义一致
4. 检查版本号命名空间是否在各处引用时保持一致

### 典型反例

| 反例类型 | 说明 |
|---------|------|
| 枚举值不一致 | 正文定义"代办"，实施例写"代办用户" |
| 错误代码命名空间交叉 | 导办方法用GUIDE_前缀，但兜底原因编码也用了GUIDE_前缀，与异常标记共享命名空间 |
| "已失效"vs"未通过" | S4置信度通过标记在表格定义中用"未通过"，在步骤汇总表中用"已失效" |

### 修复模板

- 统一为定义表中的枚举值，全文替换不一致的写法的所有出现

---

## D3：状态迁移

### 检查方法

1. 读取状态迁移表，列出所有状态×触发条件组合
2. 检查是否每个状态都有：
   - 明确的进入条件
   - 明确的退出条件（正常路径）
   - 明确的失败条件（异常路径）
   - 退出后的目标状态
3. 检查失败条件是否有对应的动作编号和分流路径
4. 检查超时/并发/崩溃场景是否在状态迁移表中有对应路径

### 典型反例

| 反例类型 | 说明 |
|---------|------|
| 未覆盖的迁移路径 | 待采集状态超时达上限→人工复核的路径未列入状态迁移表 |
| 缺少出口状态 | 人工复核状态退出条件为"人工确认结果写回"，但未说明复核通过后字段进入哪个状态 |
| 死循环 | 二次确认后仍受Score确认阈值约束，用户明示选择被算法否决 |

### 修复模板

- 在状态迁移表中增加缺失的迁移行
- 为每个状态补充明确的"退出后目标状态"列

---

## D4：公式完整性

### 检查方法

对每个公式：
1. 列出所有变量，检查每个变量是否有定义
2. 检查每个变量的取值范围是否明确
3. 检查边界条件是否有兜底处理（除零、空值、负数、超范围）
4. 检查运算顺序是否明确（如 max(0, ...) 与折扣系数的先后）

### 典型反例

| 反例类型 | 说明 |
|---------|------|
| 变量无定义 | 公式中使用"备用路径系数"，但该变量的定义段落中未给出默认兜底值 |
| 除零风险 | C_queue=1-等待时间/等待时间阈值，阈值配置为0时未兜底 |
| 运算顺序歧义 | "Score原始结果乘以不可办折扣系数"，未说明是在max(0,...)钳位前还是后 |

### 修复模板

- 补充变量定义和取值范围
- 补充边界兜底规则
- 明确运算顺序

---

## D5：错误代码分流

### 检查方法

1. 列出全部错误代码，检查每个是否有：
   - 明确的触发条件（哪个步骤、哪个子步骤）
   - 明确的写入位置（写入哪个字段）
   - 明确的分流路径（对应哪个动作编号、进入哪个状态）
2. 检查同一错误代码是否承载多种语义（过载）
3. 检查分流路径是否有区分条件（如依赖边类型是否为循环依赖边类型）

### 典型反例

| 反例类型 | 说明 |
|---------|------|
| 语义过载 | ERR_RULE_MISS承载6种不同语义（规则检索无匹配、模板配置异常、配置预检失败、外部参数缺失、持锁超时、版本快照异常） |
| 分流条件缺失 | 普通ERR_RULE_MISS和依赖环ERR_RULE_MISS分流仅依赖"依赖边类型"，但材料枚举异常的ERR_DATA_ANOMALY也走了同一分流路径 |
| 分流路径不完整 | ERR_EXTERNAL有3种失败分级（阻断/人工复核/仅标记继续），但其中"仅标记继续"路径在后续S6回退计算中未作为特殊分支处理 |

### 修复模板

- 为严重过载的错误代码拆分为独立代码
- 为区分条件不足的分流路径补充区分维度
- 补充分流路径的后续处理

---

## D6：实施例一致性

### 检查方法

1. 逐句比对实施例段落与正文步骤描述
2. 检查步骤执行顺序是否一致
3. 检查状态值、术语名称是否与定义表一致
4. 检查时序描述是否与正文的T0-T5时序约束一致

### 典型反例

| 反例类型 | 说明 |
|---------|------|
| 状态迁移时点矛盾 | 正文说S5策略命中后迁移"路径已确定"，实施例说S4硬约束过滤后即迁移 |
| 术语不一致 | 实施例中"代办用户"vs正文枚举"代办" |
| 步骤顺序矛盾 | 实施例中材料状态编号在事项确认前生成，但正文时序T0-T5说应在S4排序稳定后由S3重判定生成 |

### 修复模板

- 以正文为准修正实施例中的错误描述
- 或修正正文中的错误定义
- 确保实施方式段落能追溯到正文的具体步骤描述

---

## D7：图文一致性

### 前提条件

需 `.drawio` 或 `.xml` 格式的附图文件。启用 D7 时，先调用 `drawio-skill`（harness-ai-kit 依赖）解析附图，得到节点文本列表和连线（源→目标+标签）列表，再与正文交叉校验。

### 检查方法（依赖 drawio-skill）

1. 调用 `drawio-skill` 解析 .drawio/.xml 文件，获取：
   - 所有节点文本和ID
   - 所有连线（源节点→目标节点）及标签
2. 将提取的节点文本/连线标签与正文对应段落逐项比对：
   - 步骤编号是否对应（图2的S1-S4流程与正文S1-S4步骤描述是否匹配）
   - 状态迁移箭头是否与状态迁移表一致
   - 数据流方向是否与步骤间数据流汇总表一致
3. 检查附图说明段落是否与附图内容匹配

### drawio-skill 输出格式

调用 `drawio-skill <附图路径>` 后获得的输出：
```
## 节点（共 N 个）
| 节点ID | 节点文本 | 样式摘要 |
| 2 | 字段采集与置信度判定 | rounded=1 |

## 连线（共 M 条）
| 连线ID | 源节点 → 目标节点 | 连线标签 |
| 5 | "字段采集"(ID 2) → "规则校核"(ID 4) | 通过 |
```

本技能将节点文本与正文S1-S7步骤名称比对，连线方向与数据流汇总表的输入/输出方向比对，连线标签与状态迁移表的"下一动作"比对。
