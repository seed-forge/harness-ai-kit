# REFERENCE: 脱敏规则

采集面向测试环境，但产物（截图/台账/记录）可能进入手册、被分享或提交。必须默认脱敏。

## 硬性规则（不可协商）

1. **凭据绝不落文件**：测试账号口令、Token、API Key、Cookie、Session 一律不写入 capture-ledger、capture-trace 或截图说明；trace 中如需传值一律用 `${VAR}` 占位，登录口令永不入 trace
2. **登录页截图打码**：登录页截图必须对密码框、验证码、已填账号做打码或清空后再截
3. **本任务测试凭据**：任何测试系统的账号口令仅存在于当次执行上下文，不写入长期记忆、不入库、不进产物

## 敏感字段（截图前打码或事后标注）

- 个人信息：手机号、身份证、邮箱、真实姓名、住址
- 财务信息：金额、账号、卡号、合同价
- 系统敏感：内网 IP、服务器名、内部工号、密钥片段
- 业务敏感：客户名称、涉密项目名（按项目约定）

打码方式：截图后对敏感区域打马赛克/黑条；或在采集时先用脱敏测试数据操作。

## 台账标记

- capture-ledger 的 `redacted` 列如实标 `yes`/`no`
- 含打码的截图在 notes 简述"已对 XX 打码"
- 若某步无法脱敏（敏感信息与关键操作重叠），标 `pending` 并提请用户决定该步是否入手册

## 分享/提交前复检

- 手册导出或分享前，回扫所有截图确认无遗漏敏感信息
- trace/ledger 提交到 Git 前确认无凭据明文
