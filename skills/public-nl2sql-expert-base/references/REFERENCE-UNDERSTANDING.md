# NL2SQL 理解与抽取

## 意图识别 / 查询类型判定
- 先判定查询类型（明细/指标/排名/对比），驱动后续策略选择。
- 意图模糊时：可先做**查询改写层**（结合上下文、消解模糊指代）再判定 —— 改写前后意图非线性先后关系，可多次互调融合。

## 知识增强检索（RAG）
- 用知识库检索业务术语、字段映射、schema 关系，增强语义理解。
- **主表/表识别不能只靠向量 topN**：直接字段匹配会召回大量无关表（检索 N 张实需 2-3 张）。
  - 正确做法：语义分析 + **条件驱动反向查表**（按条件中出现的字段反查其所属表），召回后二次筛选，校验 max_tables。

## 字段/术语映射
- 业务术语 → 物理字段（"销售额"→`sales_amount`）。
- 支持多种字段类型过滤：TIME/STRING/NUMERIC/ENUM/BOOLEAN；用二级优先级匹配（field_value_type → standard_data_type）。

## 条件抽取
- 覆盖无引号值（"包含停电"）：规则模式 + LLM 兜底。
- 逻辑运算符正确识别：`A或B`、"包含X字段或Y字段" 应产出 `logic: OR`，勿默认 AND。
- **兜底触发阈值语义正确**：`min_conditions` 之类阈值要表达"规则不足"，不能因 =0 导致兜底永不触发。

## metric / 时间 / 实体
- metric：聚合与衍生指标（无效数、闭环率等）由 metric 链路生成，ranking 链路不承接。
- 时间：时间表达规范化（今年/上月/双月等）需具体实现；日期转换逻辑宜集中（如下沉到 DSL2SQL 层）。
- 实体：实体名称验证增强，避免误映射。
