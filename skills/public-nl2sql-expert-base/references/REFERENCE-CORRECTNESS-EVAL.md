# NL2SQL 正确性与评测

## 多表 JOIN 推理
- 自动推断表间关系生成最优 JOIN，避免笛卡尔积。
- 期望的 JOIN 类型要正确（如 INNER vs LEFT），由业务语义决定；关系推理要能处理外键缺失场景。
- 表数量受控：召回过多表会引入无关 JOIN，需 max_tables + 条件驱动筛选。

## SQL 正确性校验
- DSL 构建后做语法 + 语义校验；执行前拦截明显错误。
- 区分 DSL 生成正确性（NL2DSL 职责）与执行正确性（下游服务职责），职责分离便于定位。

## 评测集与自动评测（与 devlab-eval-driven-agent 配合）
- 评测集按业务模块组织（应答/推送/网格/诉求/预警…），覆盖明细/指标/排名/对比。
- 每条用例：`query` + `期望 DSL/SQL`；**SQL 标准化后比对**（sqlparse 标准化，容忍格式差异，聚焦语义）。
- Mock 掉下游执行服务（如 localhost mock API），无 Docker 环境也能跑；支持单用例/单模块快速跑。
- 每修一个 badcase → 沉淀回归用例，防复发。

## 常见错误模式（速查）
| 现象 | 根因 | 规避 |
|------|------|------|
| 主表识别错 | 只按向量匹配字段 | 语义分析 + 条件驱动反向查表 |
| LLM 兜底不触发 | 阈值语义写空(min=0) | 阈值表达"规则不足"真实语义 |
| LLM 超时丢结果 | 超时值 < 真实耗时 | 超时匹配真实耗时 + 降级 |
| OR 被当 AND | 逻辑运算符识别缺失 | 增强"或"关系识别 + prompt 示例 |
| 衍生指标缺失 | 误路由到 ranking | 稳定分类到 metric 链路 |
| datasource_id 解析失败 | 类型契约不一致(str vs int) | 契约校验（见 devlab-contract-web-server） |
