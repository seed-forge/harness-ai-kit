# 专利章节编写要求

以下要求是从团队已有专利交底参考样稿中抽取出的稳定写作规则，用于指导专利技术交底书和说明书主体撰写。

## 通用要求

### 注意事项

1. 交底书应使代理人能看懂，尤其是背景技术和详细技术方案，一定要写得全面、清楚、完整。
2. 技术公开程度应达到：本领域普通技术人员不需付出创造性劳动即可实施。
3. 若代理进一步追问技术问题，应能够基于交底书继续补充和解释。

### 总体写法要求

- 不只讲系统“有什么功能”，还要讲“如何做到”
- 不只写流程结果，还要写触发条件、输入、处理、输出
- 方法类专利应提供流程图，并提供相应系统装置
- 所有英文缩写应有中文注释
- 所有附图应有足够文字说明，不看附图也能理解方案
- 附图注释和图中关键词尽量用中文

## 一、背景技术

### 参考要求

- 介绍相关技术背景
- 描述与本发明技术最相近的现有技术
- 说明该现有技术存在的缺点
- 背景技术及现有技术方案应详细介绍，以不需再去看文献即可领会该技术内容为准

### 项目内写法要求

1. 先写技术领域和应用场景，不空泛起手
2. 再写现有主流技术路线、代表性实现方式或典型业务形态
3. 再落到最接近本方案的现有做法
4. 最后把缺陷写具体，并与后文技术方案形成呼应

## 二、技术问题

1. 不重复背景中的大段铺垫
2. 用 1 段或 2-3 条归纳出本方案拟解决的问题
3. 问题表述应可直接映射到后续技术方案和技术效果
4. 优先写成具体技术性问题，而不是抽象业务诉求

## 三、详细技术方案

1. 优先写模块、状态、规则、步骤之间的关系
2. 每个核心模块尽量交代输入、处理、输出
3. 每条关键链路尽量交代触发条件、数据来源、判断逻辑、输出结果和异常分支
4. 对容易被追问的句子，必须落到具体机制
5. 对“准确率提升”“识别更精准”“自主预判”这类表述，必须补足底层支撑机制

## 四、本技术方案的有益效果/创新点

1. 不写成市场宣传语
2. 先写技术手段差异，再写由此带来的效果
3. 尽量对应背景中的缺陷逐项回应
4. 少写泛化“体验更好”，多写具体技术原因

## 五、其它

1. 可放附图说明、预审说明、保护方向建议、待补材料
2. 若当前属于客户预审版，可在本节保留“后续权利要求抽取重点”
3. 不把核心技术机制塞到本节，核心内容仍应放在前三章或第四章
